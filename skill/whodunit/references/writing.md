# Write for the reader

Use ASD-STE100 writing principles with American spelling. Use these principles to make the report clear. Do not claim formal STE compliance without checking the full rules and dictionary.

- Use common words and active voice. Say who did what when the evidence identifies them.
- Put one idea in each sentence. Aim for 20 words or fewer when possible.
- Use one name for each thing. Define a needed technical term once.
- Keep exact file names, error messages, code names, and commands in the sources. Explain their meaning in the report.
- State the cause first. Distinguish facts, reported claims, and unknowns.
- Describe the change and its effect. Avoid slogans and repeated status labels.
- For a fix, say what changed and which tests ran. Code changes do not prove that production recovered.

The [official ASD-STE100 overview](https://www.asd-ste100.org/about_STE.html) describes the writing rules and controlled dictionary.
